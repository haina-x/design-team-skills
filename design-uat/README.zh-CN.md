# Design UAT 使用指南

[English](README.md) | [简体中文](README.zh-CN.md)

本指南介绍设计师如何使用 [`design-uat` Codex skill](SKILL.md)。

## 它能做什么

Design UAT 对照真实网页与 Figma 设计，梳理相关页面和状态，收集视觉证据并生成报告。报告会区分可复现的视觉缺陷、与选定设计基线的差异，以及需要设计澄清的问题。

报告默认使用英文；发起评审时可以指定其他语言。

## 发起评审

在同一条请求中提供评审信息：实现页面 URL、Figma 链接或 frame、要检查的页面和状态、设备或视口、重点关注内容、已接受的差异，以及报告语言。

```text
请用 $design-uat 对照以下实现与 Figma 设计，先准备一份中文 review draft。

实现页面：
Figma 链接或 frame：
要检查的页面和状态：
设备或视口：
重点关注：
已接受的差异：
报告语言：
```

如果要覆盖整页或整个模块，请明确说明。抽样一个状态（例如列表、打开的抽屉或空状态）不代表整个模块都已验收。如果网站或 Figma 文件需要登录，请确保 Codex 可以使用已授权的会话。不要为了截图提交真实业务数据；无法访问的状态会记录为受阻或未检查。

## 评审问题并决定后续

结合真实页面截图、设计参考和证据逐条查看问题，并告诉 Codex 如何处理：

- 保留，交给开发跟进
- 排除，并记录原因
- 接受为有意差异
- 与相关问题合并
- 暂缓
- 更新设计参考

如果需要改变设计基线，请先更新 Figma 并提供新的设计参考。之后让 Codex 根据你的决定更新报告，只为保留的问题准备开发 handoff。每项 handoff 应包含直接测试 URL、页面导航上下文、开发者需要采取的行动，以及可观察的验收标准。

把生成的 `report.html` 和 `issue-register.csv` 放到团队使用的设计评审记录或开发任务中，方便讨论和跟踪。文件会生成给你；请按团队约定把它们添加到对应位置。

## 实现后复测

实现改动可供检查后，让 Codex 使用相同的页面和状态、对照已确认的 Figma 基线重新评审。要求保留原有 issue ID，并且只有新证据支持时才把问题标记为已解决。如果设计已经修改，请先更新或确认新的 Figma 基线，再复测。

## 输出和限制

- `report.html` 包含评审背景、问题清单和视觉证据。
- `issue-register.csv` 方便团队筛选和跟踪问题。
- 提供验收标准时会生成 `acceptance-checklist.csv`。
- 静态截图不能证明键盘操作或其他运行时行为；未检查的状态会作为限制记录。
- skill 不会为了取证而提交表单或执行真实业务变更，也不会自动把报告发送给团队。
